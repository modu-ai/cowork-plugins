한눈에 보는 결론

MCP(Model Context Protocol) — AI가 외부 서비스(쇼핑몰·회계·문서변환 등)와 대화하기 위한 표준 연결 규격입니다. 우리 플러그인 중 12개가 이 연결을 씁니다.

맥 쪽은 깨끗합니다. macOS × Claude, macOS × Codex 두 조합에서 발견된 실사용 결함이 없습니다. 문제는 전부 윈도우 축과 사전 준비물 안내에 몰려 있습니다.

결함 — 높음

F-1 · doc-pdf가 윈도우에서 PDF를 못 만든다 높음

weasyprint(위지프린트) — HTML을 PDF로 바꿔 주는 파이썬 도구입니다. 그런데 이 도구는 파이썬만으로 돌아가지 않고, 글자를 실제로 그려 주는 시스템 라이브러리(Pango/GTK)를 따로 요구합니다. 맥·리눅스에는 대개 있지만 윈도우에는 없습니다.

  • 근거 — doc-pdf/SKILL.md:175의 트러블슈팅 행이 cannot load library 'libpango...' 오류에 대해 Debian/Ubuntu와 macOS 해법만 제시합니다. 윈도우 행이 없습니다.
  • 근거 — 같은 파일 64·173행의 한글 폰트 설치 안내도 brew(맥)와 apt(리눅스)뿐입니다.
  • 영향 — 윈도우 사용자가 "PDF로 만들어줘"라고 하면 모듈 로드 실패로 끝납니다. 오류 메시지가 영문 라이브러리 이름이라 비개발자는 원인을 짚을 수 없습니다.
  • 조치 — 트러블슈팅 표에 윈도우 행 추가(GTK for Windows 런타임), 또는 윈도우에서는 headless Chromium 경로로 폴백.
worked example — 윈도우 사용자 홍길동 씨의 경우
① 앱에서 "이 보고서 PDF로 저장해줘" 입력 → ② doc-pdf 스킬 발동 → ③ from weasyprint import HTML 실행 → ④ OSError: cannot load library 'libpango-1.0-0' → ⑤ 스킬이 문서의 트러블슈팅 표를 읽음 → ⑥ 표에 있는 건 apt install ...(리눅스)과 brew install pango(맥)뿐 → ⑦ 안내할 수 있는 해법이 없음.

F-2 · Node.js 설치 안내가 문서 어디에도 없다 높음

npx(엔피엑스) — Node.js에 딸려 오는 실행 도구입니다. 우리 플러그인 4종이 이걸로 MCP 서버를 띄웁니다. 즉 Node.js가 없으면 그 4종의 연동 기능이 통째로 안 뜹니다. 그런데 온라인 문서 어디에도 Node.js를 깔라는 말이 없습니다.

  • 해당 플러그인 — moai-accountant, moai-analyst, moai-coworker(서버 dart), moai-officer(서버 kordoc)
  • 근거 — www/content 전체를 훑었을 때 Node.js/nodejs.org 매치는 moai-agents/officer.md와 아카이브 릴리스 노트뿐. 설치 문서 3종은 전부 0건입니다.
  • 대조군 — 같은 성격의 준비물인 uv는 plugins/mcp/install.md에 맥(설치 스크립트)·윈도우(winget, PowerShell) 안내가 모두 있습니다. Node.js만 같은 대접을 못 받고 있습니다.
  • 영향 — OS 축이 아니라 맥·윈도우 공통 결함입니다. 그래서 심각도가 높습니다.
  • 조치 — plugins/mcp/install.md에 "Node.js 설치" 절을 uv 절과 같은 형식으로 추가 (윈도우는 winget install OpenJS.NodeJS.LTS).
왜 이게 특히 위험한가
Node.js가 없으면 오류가 뜨지 않습니다. MCP 서버가 그냥 목록에서 빠질 뿐이라, 사용자는 "전자공시 조회가 원래 안 되는 기능인가 보다"라고 오해합니다. 실패보다 조용한 실패가 진단하기 어렵습니다.

결함 — 중간

F-3 · 등기부 자동화 스킬이 맥 전용 명령을 안내 중간

  • 근거 — legal-iros-registry-automation/SKILL.md:51 
    python3 -m venv .venv && source .venv/bin/activate
  • 문제 ① — source .venv/bin/activate는 맥·리눅스 전용입니다. 윈도우는 .venv\Scripts\activate.
  • 문제 ② — python3라는 이름의 명령은 python.org의 윈도우 설치본에 생기지 않습니다. 윈도우는 python 또는 py입니다.
  • 조치 — 맥용·윈도우용 두 줄을 나란히 표기.

F-4 · 한국어 윤문 스킬의 python3 5곳 중간

  • 근거 — korean-humanize/SKILL.md 72·89·108·212·247행이 모두 python3로 시작합니다.
  • 문제 — F-3과 같은 원인. 윈도우 python.org 설치본에는 python3.exe가 없습니다(마이크로소프트 스토어 배포본에만 있습니다).
  • 좋은 소식 — 불려 가는 파이썬 스크립트 6종 자체는 이식성 문제가 전혀 없습니다. 경로는 os.path 기반, 파일 열기 12곳 전부 인코딩 명시, 윈도우 줄바꿈(CRLF)도 sanitize_text.py:91-93에서 명시적으로 정규화합니다. 껍데기 명령어 이름만 고치면 됩니다.
  • 조치 — python3 → python (또는 uv run python)으로 통일.

결함 — 낮음

F-5 · 폰트 file:// 주소 조립 — 지금은 안 터지는 잠복 결함

  • doc-pdf/SKILL.md:81이 f"src:url('file://{FONT_DIR}/...')"로 주소를 만듭니다. 윈도우에서 FONT_DIR은 C:\Users\... 형태라, file://C:\...는 유효하지 않은 주소가 됩니다.
  • 지금은 발화하지 않습니다 — assets/fonts/에 실제 폰트 파일이 없고(LICENSE.txt·README.md뿐) 코드에 .exists() 가드가 있어 이 줄이 실행되지 않습니다. 폰트를 번들하는 순간 터집니다.
  • 조치 — 번들 전에 Path(...).as_uri()로 교체.

F-6 · Codex 매니페스트가 agents/를 선언하지 않음 미검증

  • 확인한 사실 — 18개 플러그인 모두 agents/*.md를 2개씩(총 32개) 갖고 있는데, .codex-plugin/plugin.json은 "skills"·"mcpServers"만 선언하고 "agents" 키가 없습니다. (Claude 쪽도 같지만, Claude는 규약상 자동 탐지합니다.)
  • 단정하지 않는 이유 — Codex 런타임이 agents/를 자동으로 찾는지 실제로 실행해 확인하지 않았습니다. 확인 없이 "결함"이라고 부르면 근거 없는 주장이 됩니다.
  • 조치 — Codex에서 플러그인 1종을 실제로 로드해 에이전트가 노출되는지 눈으로 확인.

F-7 · 배포 패키지에 유지보수용 bash 스크립트 1개

  • plugins/moai-coworker/scripts/korean-slop-lint.sh — 실행 비트가 걸린 bash 스크립트입니다. 어떤 SKILL.md도 이걸 부르지 않으므로 동작에는 영향이 없습니다.
  • 조치 — 저장소 scripts/로 옮기거나 배포에서 제외.

F-8 · 문서 안에 남은 맥 전용 표기 4곳

  • moai-media/.mcp.json:4 주석 — uv 설치 명령이 맥·리눅스 셸 형태만 (윈도우 병기 없음)
  • doc-html-slide/references/html-runtime.md:116 — file:///... 유닉스 형태 예시
  • doc-html-slide/references/image-backend-policy.md:80 — /tmp/hero.png
  • doc-html-report/references/design-tokens.md:10 — /tmp/html-eff/

참고 — 개발 저장소 한정 (사용자 영향 없음)

루트 .mcp.json의 chrome-devtools·context7·playwright 3종이 "command": "/bin/bash"와 -l -c를 씁니다. 이 파일은 개발 저장소 전용이라 마켓플레이스로 배포되지 않으므로 사용자에게 영향이 없습니다. 다만 §범용성 원칙의 검사 명령이 여기서 매치를 내므로, 검사 범위를 plugins/*/.mcp.json으로 한정하거나 루트도 npx 직접 호출로 정리하면 검사 신호가 깨끗해집니다.

준비물별 플러그인 분포

MCP 서버 정의를 가진 플러그인 12종 기준 (한 플러그인이 두 종류를 함께 쓰는 경우 중복 계상)

확인하지 못한 것 (미검증)

이 리포트는 코드와 문서를 읽어서 낸 결론입니다. 실제 윈도우 컴퓨터에서 설치해 돌려 본 결과가 아닙니다. 그래서 아래는 "문제 없음"이 아니라 "확인 안 함"입니다.

  • 실제 Windows 머신에서의 설치·기동 검증 — 전부 정적 분석
  • Codex 런타임 실제 로드 검증 (F-6을 단정하지 않은 이유)
  • 원격 HTTP MCP 8종의 실접속 — OS와 무관하지만 가용성 자체는 확인 안 함
  • 스킬 224개 전문 정독 — 패턴 검색으로 훑었으므로 패턴 밖 하자는 남아 있을 수 있음
  • 제3자 MCP(dart, kordoc, elevenlabs-mcp)의 윈도우 동작 — 원저작자 책임 영역

잔여 위험

  • npx 계열은 Node.js 유무에 따라 조용히 실패합니다 — 오류 없이 도구 목록에서 빠지므로 사용자가 "원래 없는 기능"으로 오인합니다.
  • uv·npx는 첫 실행 때 패키지를 내려받으므로, 사내망·오프라인 환경에서는 OS와 무관하게 기동에 실패합니다.

moai-threads-poster — Threads 자율 발행 플러그인

📅 2026-08-04 👤 GOOS 오빠 상태: 계획 (승인 대기)

🎯 한눈에 보기 (TL;DR)

"매일 정해진 시간 + 정해진 주제로, 내가 최종 승인한 글을 Threads에 자동 발행"하는 새 플러그인을 만든다. 외부 월정앵 도구(typefully 등) 없이 Threads API를 직접 연결해 $0로 운영한다.

확정된 결정 4가지

  1. 직접 Threads API MCP 서버 구축 (Python/uv, moai-seller 패턴) — API 자체 무료
  2. SQLite 발행 큐 + macOS launchd — 세션을 꺼도 매일 지정 시간에 자동 발행
  3. 발행 직전 최종 승인 — AI가 원고 생성 → 내가 "올려" 클릭 → 시간 되면 자동 발행
  4. Threads 전용 — Facebook 개인 계정은 API 불가(정책)이므로 제외. 페이지는 추후 추가 가능

1. 왜 직접 구축인가 (비용 비교)

"매일 발행"이 핵심 요구라, 외부 서비스의 무료 한도와 플랫폼 지원을 먼저 확인했다.

방식월 비용매일 발행ThreadsFacebook공수
직접 Threads API MCP 선택$0가능(직접 큐)✅❌(개인불가)높음
typefully 재사용Pro 결제 필요*서버 예약✅❌ 미지원낮음
post-bridge 재사용Creator/Pro 결제서버 예약✅✅(페이지)낮음

* typefully Free는 월 15 posts 제한 — 매일 올리면 한 달 ~30 posts 필요해 Pro 결제가 필수. typefully는 Facebook 미지원(X·LinkedIn·Threads·Bluesky·Mastodon만). 출처: typefully.com/pricing

⚠️ Facebook 개인 계정은 API로 못 올립니다 Meta가 2018년 publish_actions 권한을 폐지했습니다. Graph API로 포스팅 가능한 것은 페이지·그룹뿐이며, 개인 타임라인에는 API 발행이 불가합니다. 따라서 사용자 결정대로 Threads만 진행합니다.

2. 전체 아키텍처 (발행 흐름)

4개 주체가 협력합니다: 사용자(주제·승인) → Claude Code + MCP(원고·큐 관리) → launchd(발행 트리거) → Threads API(실제 발행).

① 주제 달력(markdown) ──사용자가 미리 작성──▶ 매일 1개 주제 │ ② Claude Code (content-sns-content 스킬) │ 주제 → 500자 이내 한국어 Threads 원고 생성 ▼ ③ threads-poster MCP ── draft(초안)로 SQLite 큐에 저장 ── 상태: PENDING │ ④ 사용자 "올려" 승인 ──▶ 상태: APPROVED + 발행 시각 지정 │ ⑤ macOS launchd (매일 09:00 KST) ── runner.py 실행 │ 큐에서 APPROVED + 시각 도달 항목 꺼냄 ▼ ⑥ Threads API 2단계 발행 │ POST /{user}/threads → media container 생성 │ POST /{user}/threads_publish → 실제 게시 (평균 30초 대기) ▼ ⑦ 상태: PUBLISHED + 게시물 URL 기록 ──▶ 사용자에게 결과 보고

4. Threads API 핵심 요약

공식 문서(developers.facebook.com/docs/threads)에서 확인한 핵심:

2단계 발행 프로세스

# 1단계: 미디어 컨테이너 생성
curl -X POST \
  -d "media_type=TEXT" \
  -d "text=<글 내용>" \
  -d "access_token=" \
  "https://graph.threads.com/v1.0//threads"
# → { "id": "" }

# 2단계: 발행 (평균 30초 대기 권장)
curl -X POST \
  -d "creation_id=" \
  -d "access_token=" \
  "https://graph.threads.com/v1.0//threads_publish"
# → { "id": "" }

토큰·권한·제한

항목값
인증OAuth 2.0 — short-lived(1시간) → long-lived(60일) → GET /refresh_access_token 갱신
권한 부여 유효기간90일 (공개 프로필만 갱신 가능; 비공개는 재승인 필요)
필수 권한threads_basic(모든 엔드포인트), threads_content_publish(발행)
텍스트 제한500자 (이모지는 UTF-8 바이트 수로 계산)
발행 한도24시간당 250개
링크5개 이하 (2025-12-22부터 초과 시 THREADS_API__LINK_LIMIT_EXCEEDED 실패)
미디어이미지(JPEG/PNG, 8MB), 영상(MP4/MOV) — 공개 서버 URL에서 Threads가 다운로드
캐러셀최대 20개 (이미지/영상 혼합)

5. 스케줄링 — 세션 꺼도 매일 발행되게

Claude Code 자체 스케줄러(CronCreate)는 세션이 켜져 있을 때만 작동한다. "매일"을 보장하려면 운영체제 수준 스케줄러가 필요하다.

✅ 선택한 방식: macOS launchd + SQLite 큐
  • SQLite 큐(queue.py): 모든 발행 후보를 저장. 상태 = PENDING → APPROVED → PUBLISHED
  • launchd plist(~/Library/LaunchAgents/com.moai.threads-poster.plist): 매일 지정 시각에 runner.py 실행
  • runner.py: APPROVED + 발행 시각 도달 항목을 꺼내 Threads API로 발행
  • 컴퓨터가 켜져 있으면 세션/브라우저와 무관하게 동작 (macOS 전용; Linux는 cron, Windows는 작업 스케줄러로 동일 패턴 확장 가능)

6. 승인 흐름 (자동 아닌 자율)

상태의미주체
PENDINGAI가 원고 생성해 큐에 넣은 초안Claude (자동)
APPROVED사용자가 "올려" 승인 + 발행 시각 지정사용자 (필수)
PUBLISHEDlaunchd가 발행 완료, 게시물 URL 기록launchd (자동)
FAILEDAPI 오류/토큰 만료 등 — 재시도 또는 사용자 알림시스템
🔐 안전장치 APPROVED 없이는 절대 발행되지 않는다. 이것이 "자동이 아닌 자율"의 핵심 — 사용자가 매 글마다 명시적으로 승인해야만 발행 큐에 진입한다.

8. 구축 전 알아야 할 숙제 (3가지)

1. Meta App 등록 + App Review (사용자 직접, 1회성) Threads API를 쓰려면 개발자 콘솔에서 Meta App을 만들고, threads_content_publish 권한으로 App Review를 받아야 한다. 본인만 쓸 때는 테스터 등록으로 바로 가능하지만, 공개 자동화에는 리뷰 통과 + 앱 게시가 필요하다.
2. 액세스 토큰 60일 갱신 long-lived 토큰은 60일마다 갱신해야 한다. token_store.py가 만료 임박 시 자동 갱신(GET /refresh_access_token)하지만, 90일 권한 부여 만료 시에는 재인증이 필요할 수 있다(공개 프로필이면 자동 연장).
3. 이미지·영상 공개 호스팅 Threads는 미디어를 "공개 URL"에서 받아간다(직접 파일 전송 ❌). 발행할 미디어를 올릴 공개 서버가 필요하다 — 후보: 기존 웹서버, GitHub Pages, Cloudflare R2, 간이 정적 호스팅. 텍스트 전용 발행이면 불필요.

9. 책임 경계 (기존 moai-marketer와)

기존 moai-marketer 플러그인은 마케팅/광고(typefully·post-bridge·meta-ads 연동)를 담당한다. 새 moai-threads-poster는 개인 Threads 자율 발행에 집중하며, 원고 생성만 content-sns-content 스킬을 재사용해 겹침을 피한다.

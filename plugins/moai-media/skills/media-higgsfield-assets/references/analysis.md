# analysis.md — 완성 영상 분석 (바이럴 예측)

> `media-higgsfield-assets` | 이미 만들어진 영상이 주의를 얼마나 붙잡는지 점수화하는 경로.
> 미디어를 만들지 않고 **텍스트 리포트**를 반환한다.

**Evidence tier:** 2차 (Higgsfield 공식 스킬 `higgsfield-generate` v0.12.0, MIT — Virality Predictor 절) + 라이브 MCP 도구 존재 관측

---

## 1. 무엇인가

Virality Predictor는 완성된 영상 크리에이티브를 **주의(attention)의 객관적 대리 지표**로 평가한다. 사람에게 물어보지 않고 영상 자체에서 훅 강도·유지력·주의 분산 위험을 추정한다.

기술 식별자는 `brain_activity`지만, **사용자에게는 "바이럴 예측기"라는 제품명으로 부른다.** 내부 id를 노출하지 않는다.

입력은 영상 1개, 출력은 텍스트 리포트다. 프롬프트는 필요 없다.

---

## 2. 언제 라우팅하나

아래 요청은 생성이 아니라 분석이다. 출력이 텍스트라는 이유로 "텍스트 모델"로 잘못 분류하지 않는다 — **입력이 영상이면 영상 분석이다.**

- "이 영상 분석해줘"
- "이 광고 점수 매겨줘"
- "훅이 괜찮은지 봐줘"
- "바이럴 가능성 어때?"
- "리텐션 위험 있어?"
- "어느 구간이 약해?"

---

## 3. 결과 해석

리포트에서 사용자에게 전달할 항목:

| 항목 | 뜻 |
|---|---|
| 종합 점수 | 전체 주의 유발력 |
| 피크 초 | 훅이 가장 강하게 걸리는 시점 |
| 유지(sustain) 점수 | 초반 이후 주의가 얼마나 이어지는지 |
| 강한/약한 구간 | 재편집 우선순위 |
| 리포트 URL | 시각 리포트 링크 |

**방향 해석:**
- Visual / Auditory / Language / Attention 점수는 **높을수록** 자극과 집중이 강하다.
- Default Mode 점수는 **낮을수록** 좋다 — 시청자의 딴생각(mind-wandering)이 적다는 뜻이다.

이 마지막 항목은 방향이 반대라서 자주 오독된다. 리포트를 옮길 때 방향을 함께 적는다.

---

## 4. 노출하지 않을 것

리포트에는 원시 렌더 아티팩트(정점 맵 바이너리, 예시 URL 등)가 함께 담긴다. 이것들은 구현 세부이며, 사용자가 원시 데이터를 명시적으로 요구할 때만 언급한다. 기본 보고는 **점수 + 리포트 링크**까지다.

---

## 5. 안티패턴

- **분석 결과로 영상이 나온다고 기대하게 두기** — 출력은 텍스트다. 시작할 때 명확히 한다.
- **`brain_activity`라는 내부 id를 사용자에게 노출** — 제품명은 "바이럴 예측기"다.
- **Default Mode를 높을수록 좋다고 보고** — 반대다.
- **영상 없이 호출** — 영상 1개가 필수 입력이다.
- **아직 편집 중인 소재를 최종 점수로 취급** — 완성 크리에이티브 평가 도구다. 중간 컷 점수를 최종 성과로 단정하지 않는다.

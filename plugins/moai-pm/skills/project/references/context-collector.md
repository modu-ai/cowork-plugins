# context-collector.md — 맥락 수집 프로토콜 (project 스킬)

## 개요

project 스킬의 스킬 체인 실행에 필요한 사용자 맥락을 체계적으로 수집하는 프로토콜이다. 맥락 충분성 등급, 커버리지 기반 라운드 설문, 모호성 감지, 반복 방지를 통해 효율적인 수집을 구현하고, 수집된 맥락의 **적용 규칙**(§5)까지 정의한다.

---

## 1. 맥락 충분성 등급

### A등급 — 필수 (프로젝트 AGENTS.md에서 즉시 획득)

프로젝트 `AGENTS.md`의 "프로젝트 개요" 섹션에서 읽어온다: 프로젝트 목적, 주요 산출물, 대상 독자·고객, 톤·형식 제약, 설치 플러그인. **글로벌 프로필은 사용하지 않는다** — 프로젝트 `AGENTS.md`가 유일한 맥락 소스다.

### B등급 — 핵심 (80% 이상 충족 권장)

산출물별 도메인 맥락. 첫 라운드에 필수 축과 함께 배치하고, 남은 공백은 다음 라운드로 이월한다.

**질문 생성 규칙**: (1) 선택한 스킬 체인이 무엇을 만드는지 파악 → (2) 이미 아는 맥락은 재질문하지 않음 → (3) 부족한 도메인 맥락만 질문 슬롯에 올림 → (4) 라운드 수를 고정하지 않고 충분성으로 판정한다.

### C등급 — 보강 (남는 슬롯에 합류)

배경·동기, 판단 근거, 팀 규모, 업무 일정/마감, 주요 과제, 예산 제약. **별도의 텍스트 대화 심화 인터뷰를 열지 않는다** — 필요한 축을 선택지 질문으로 변환해 라운드에 함께 낸다.

---

## 2. 맥락 수집 플로우 (커버리지 기반 · 라운드 무제한)

**[HARD] 정본은 `SKILL.md` §Socratic Interview다.** 거기서 8렌즈로 **이 프로젝트의 축을 도출**하고, 이 문서는 도출된 축을 어떻게 채우는지의 절차만 다룬다. **축은 고정 목록이 아니다** — 프로젝트 설명에서 매번 새로 뽑으며, 해당 없는 렌즈는 버린다. 민감도(H)만 전 프로젝트 공통 필수다.

**질문 총량에 상한을 두지 않는다.** 종료를 정하는 것은 라운드 수가 아니라 커버리지다. 다만 `AskUserQuestion` 한 호출은 **최대 4질문 × 각 4옵션**이라는 도구 상한이 있으므로, 더 묻는 방법은 **라운드를 더 도는 것**이다.

### 2-1. 사전 차감 (질문 전에 먼저 뺀다)

묻기 전에 이미 아는 것을 걷어낸다. 순서대로 훑어 커버리지 표의 칸을 미리 채운다.

1. 진입 발화에서 추출 가능한 축
2. 기존 `./AGENTS.md` 프로젝트 개요
3. `.moai/context.md` 누적 맥락
4. `.moai/config.json`의 `coverage` 스냅샷 (재개 시)

남은 칸이 `missing`이다. **정보 이득이 큰 순으로 정렬**하되, 필수 축을 항상 앞에 둔다.

### 2-2. 라운드 실행

매 라운드 `missing` 상위 **4개를 한 호출에 묶어** 낸다. 남은 축이 4개 미만이면 그만큼만 낸다.

- 질문을 1개씩 쪼개 연속 호출하지 않는다
- 모든 옵션에 `description`을 붙인다(빈 설명 금지). 첫 옵션에만 `(권장)`
- **첫 라운드부터** 「지금 아는 것으로 진행」 선택지를 함께 배치한다
- **매 라운드 진행률을 알린다** — "8영역 중 N영역 확인" 정도. 끝이 안 보이는 인터뷰가 가장 지치게 만든다

### 2-3. 라운드 간 판정

각 축을 **충족 / 유예 / 미확인** 셋 중 하나로 기록한다.

| 응답 | 판정 |
|---|---|
| 선택지 선택 또는 구체적 자유입력 | **충족** |
| 「모르겠다」·「나중에」·「지금 아는 것으로 진행」 | **유예** — 가정값을 `.moai/context.md`에 적고 무엇을 가정했는지 알린다 |
| 무응답·모호·앞선 답과 상충 | **미확인** — 다음 라운드에 **좁혀서** 다시 낸다(같은 질문을 그대로 반복하지 않는다) |

### 2-4. 종료

**필수 축이 전부 충족 또는 유예이고 미확인이 0**이면 설계로 넘어간다. 라운드 수는 미리 정하지 않는다.

두 가지 예외가 있다.

- **㉒ 민감도는 유예를 허용하되 기록은 반드시 남긴다.** 끝내 답이 없으면 `unknown`으로 저장하고, `unknown`은 외부 전송을 **하지 않는** 쪽으로 처리한다(`AGENTS.md` §6-3)
- **고위험 산출물의 유예 축**(계약·법무·재무·대외 발송)은 생성을 멈추고 명시적으로 다시 묻는다

## 3. 반복 제한 및 방지

라운드 수를 미리 고정하지 않는다. **커버리지 체크리스트의 필수 축이 전부 충족 또는 유예이고 미확인이 0**이면 종료한다(§2-4). 「지금 아는 것으로 진행」 선택지는 **첫 라운드부터** 배치해 사용자가 언제든 끊을 수 있게 한다. `./AGENTS.md` 프로젝트 개요 + 현재 세션 수집 맥락을 우선 재사용해 반복 수집을 방지한다.

## 4. 모호성 감지 규칙

신호(다중 선택 "기타", 저신뢰도 응답, 상충 답변, 도메인 키워드 부재, 목적-요청 불일치)를 **라운드 종료 시 한꺼번에 집계**하고, 감지된 신호 전부를 **다음 한 라운드**로 묶어 해소한다(신호 1개당 1회 호출 금지). 해소 시도가 2회를 넘으면 "일부 정보가 불명확하지만 진행 가능합니다"로 전환한다.

## 5. 저장 및 적용

### 5-1. 저장 위치

수집된 맥락은 **Phase 6에서 AGENTS.md 본문**(프로젝트 개요·스킬 체인 섹션)에 기록되며, 별도 컨텍스트 파일이나 글로벌 프로필을 만들지 않는다. 인터뷰 답변 → `AGENTS.md` "프로젝트 개요"에 반영. 산출물별 스킬 체인 → `AGENTS.md` "프로젝트 워크플로우" 섹션에 기록. 세션 종료 후에는 `AGENTS.md`가 단일 소스다(`CLAUDE.md`는 이를 임포트하는 포인터일 뿐 별도 내용을 담지 않는다).

### 5-2. 맥락 적용 규칙 (HARD — 수집된 맥락의 사용)

저장된 맥락(`AGENTS.md` 프로젝트 개요 + `.moai/context.md` + 세션 임시 저장)을 **사용**할 때의 규칙:

1. **선택적 적용** — 맥락은 현재 요청과 관련 있을 때만 골라 쓴다.
2. **자연스러운 반영** — 적용할 때는 원래 알던 것처럼 녹인다. 어디서 가져왔는지 티 내지 않는다.
3. **메타 코멘터리 금지** — "저장된 맥락에 따르면", "제가 기억하기로는", "프로젝트 개요를 보니" 같은 회수 서술을 응답·산출물에 쓰지 않는다.
4. **재진입(resume) 세션 주의** — 설치 후 "이어서 진행"으로 돌아온 세션은 캐시된 맥락을 다시 읽는 순간이라 메타 코멘터리가 특히 빈발한다. 재개 인사에서도 맥락은 자연스럽게만 반영한다.

이 규칙은 생성 `AGENTS.md`의 `맥락 적용 규칙` HARD 블록과 쌍이다(`agentsmd-generator.md` 참조) — 셋업 시점(본 파일)과 런타임(생성 AGENTS.md) 양쪽에서 같은 규칙이 적용된다.

---

## 6. 컨텍스트 갱신 트리거

사용자가 `AGENTS.md`를 직접 수정한 경우, 새 산출물 유형(스킬 체인)을 추가하는 경우, 평가 점수가 낮은 경우, 사용자가 명시적으로 재수집을 요청한 경우.

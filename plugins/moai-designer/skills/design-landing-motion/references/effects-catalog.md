## 0. 왜 하나만인가

시그니처 효과는 방문자가 **기억하는 그것**이다. 둘을 넣으면 서로의 인상을 지운다. 곁들이는 리빌 애니메이션은 얼마든지 좋지만, "이 사이트 뭐였지?"의 답은 하나여야 한다.

그리고 **컨셉 스파인을 갚는 것**을 고른다. "정밀"이 스파인이면 초점·계측 물리를, "상승"이면 시차 깊이를, "축적"이면 쌓임·넘김을 고른다. 브리프에 짝의 근거를 한 문장 적는다.

---

## A. 필름 스크럽 — 스크롤이 영상을 재생한다

| id | 효과 | 쓸 곳 |
|---|---|---|
| **A1** | **단일 히어로 스크럽.** 승인된 히어로 스틸에서 뽑은 5초 클립(푸시인·랙포커스·피사체 회전·빛 스윕). 프레임으로 분해해 스크롤 진행도에 바인딩 | 검증된 기본값. 처음이면 여기서 시작 |
| **A2** | **장편 챕터 스크럽.** 클립 2~4개(같은 그레이딩, 다른 비트)를 긴 핀(300~500vh)에 태우고, 챕터 사이에 텍스트 카드·수치 리드아웃이 교대 | 페이지에 다른 무거운 비트가 적을 때만 |
| **A3** | **제품 턴테이블.** 같은 제품의 다각도 컷(참조 고정으로 동일성 유지) → 프레임 스크럽 = 스크롤로 제품을 돌린다 | 물성 있는 제품 |

**주의:** 프레임 스크럽은 이미지 수가 많아 용량이 커진다. 최적화한 MP4를 직접 스크럽하거나, 프레임을 쓴다면 폭·품질을 낮춰 총량을 관리한다. 시작 프레임과 끝 프레임이 **달라야** 스크럽이 보인다.

## B. 레이어 깊이 — 한 장이 입체가 된다

| id | 효과 | 쓸 곳 |
|---|---|---|
| **B1** | **컷아웃 시차 리그.** 히어로에서 피사체를 누끼로 분리하고, 뒤에 배경판을 따로 생성. 3~5겹을 스크롤·커서에 다른 속도로 움직인다 | **가성비 최고.** 싸고 튼튼하고 효과가 크다 |
| **B2** | **그레이딩 전환 쌍.** 같은 구도를 어둡게/밝게 두 벌 생성해 커서 스포트라이트나 스크롤로 크로스페이드 | "사이트가 나를 알아본다"는 인상 |
| **B3** | **3D 피사체 씬.** 히어로 → GLB 변환 → 스크롤 카메라 오빗 + 커서 틸트 | 가장 화려하고 가장 비싸다 |

B1은 WebGL 없이 CSS `transform`만으로 된다. 첫 시도로 권한다.

## C. 캔버스·픽셀 — 이미지 자체가 살아 있다

| id | 효과 | 쓸 곳 |
|---|---|---|
| **C1** | **디스플레이스먼트/리퀴드 호버.** 히어로를 WebGL 평면에 올리고 커서로 일렁이게 | 절제하면 에디토리얼과도 어울림 |
| **C2** | **파티클 디졸브.** 히어로를 캔버스 파티클로 샘플링해 로드 시 모이고 스크롤에 흩어진다 | 데이터·기술·AI 스파인 |
| **C3** | **스크롤 마스크 리빌.** 거대한 활자나 도형 안에서 페이지가 열리고, 스크롤로 마스크가 확장돼 풀블리드가 된다 | 강한 오프닝 |

C1·C2는 WebGL이 필요하다 → `threejs-patterns.md`. C3는 `clip-path`만으로도 된다.

## D. 공간 레이아웃 — 페이지가 이상하게 움직인다

| id | 효과 | 쓸 곳 |
|---|---|---|
| **D1** | **수평 시네마 레일.** 핀된 구간에서 와이드 파노라마를 가로로 훑고 콘텐츠 카드가 레일에 실린다 | 스크롤 축이 꺾이는 것 자체가 놀라움 |
| **D2** | **스티키 스택 챕터.** 풀블리드 챕터가 서로 위로 쌓이고 벗겨진다. 챕터마다 자기 플레이트와 핀된 타이포 | 튼튼하고 에디토리얼 친화 |
| **D3** | **키네틱 타이포 오프너.** 거대 활자를 스크롤에 안무 — 글자별 스태거, 가변폰트 축 애니메이션, 줄마다 다른 트랙 | 브랜드 목소리가 곧 타이포일 때 |

D2는 가장 실패 확률이 낮다. 시간이 없으면 D2.

## 시그니처로 금지 (곁들임으로는 허용)

- 자동재생 배경 루프만 있는 것 (수동적)
- 일반 페이드인 리빌
- 인터랙션 없는 텍스트 뒤 파티클
- 마퀴 띠
- 카드 호버 틸트

이것들은 "우리 사이트의 놀라움은 무엇인가"의 답이 될 수 없다.

## 구현 계약 (전 계열 공통)

- **초기 페인트 완결.** 프레임 1 / 레이어 스택 / 마스크 해제 상태가 JS 인터랙션 전에 렌더된다.
- **입력→반응이 물리적으로 느껴질 것.** 스크럽은 진행도에 부드럽게(scrub 0.5~1), 커서는 스프링으로. 프레임마다 상태를 갱신하지 않는다.
- **저감모션:** 핀 없이 완성된 최종 상태를 정적으로.
- **모바일:** 의도적으로 열화시킨다. 커서 효과 → 스크롤 대응, 긴 핀 → 짧게, 턴테이블 → 스와이프 시퀀스. 브리프에 무엇이 어떻게 바뀌는지 적는다.

---

## 반복 방지 원장 (6축 중 4축 이상 달리하기)

같은 세션에서 두 번째 랜딩을 만들 때, 직전 빌드와 아래 6축을 비교해 **최소 4축을 다르게** 한다.

1. 팔레트 계열
2. 타이포 페어링
3. 히어로 구조 (이미지-캔버스 / 분할 / 마스크 / 레일)
4. 시그니처 효과 (이 카탈로그)
5. CTA 형태 세트
6. 모서리·테두리 언어 (각진 / 둥근 / 알약 / 헤어라인)

**첫 빌드라 비교 대상이 없다면** 브리프의 물성 세계(그 사업이 실제로 만지는 명사 — 강철·종이·수증기·이끼·비닐)에서 6축을 끌어낸다. 이때 적은 직전 빌드가 아니라 **모델의 통계적 기본값**이다. 어떤 선택이 흔한 템플릿에 있어도 어색하지 않아 보이면, 그 축은 다시 굴린다.

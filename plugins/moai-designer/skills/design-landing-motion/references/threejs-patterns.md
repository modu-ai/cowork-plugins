# threejs-patterns.md — WebGL·3D 패턴

> `design-landing-motion` | C계열(캔버스·픽셀)·B3(3D 씬)을 고른 경우에 읽는다. DOM 모션은 `motion-craft.md`.

**Evidence tier:** 3차 (three.js·R3F 통용 패턴 정리. 구체 API는 버전에 따라 달라지므로 설치된 버전의 문서로 확인한다)

---

## 0. 먼저 — WebGL이 정말 필요한가

WebGL은 비용이 크다. 번들·GPU·배터리·실패 가능성 전부. **CSS로 되는 것을 WebGL로 하지 않는다.**

| 하려는 것 | WebGL 필요? |
|---|---|
| 레이어 시차 (B1) | ❌ CSS `transform`이면 충분 |
| 마스크 리빌 (C3) | ❌ `clip-path`로 대부분 가능 |
| 스티키 스택 (D2) | ❌ `position: sticky` |
| 수평 레일 (D1) | ❌ transform + 스크롤 진행도 |
| 프레임 스크럽 (A계열) | ❌ canvas 2D면 충분 |
| 이미지 왜곡·일렁임 (C1) | ✅ 셰이더 필요 |
| 파티클 디졸브 (C2) | ✅ (수천 개 이상이면) |
| 3D 메시 오빗 (B3) | ✅ |

위 표에서 ❌인데 WebGL을 쓰고 있다면 설계를 다시 본다.

---

## 1. 스택 선택

| 환경 | 조합 |
|---|---|
| React / Next | `three` + `@react-three/fiber` + `@react-three/drei` |
| 정적 (Hugo·Astro·순수 HTML) | `three` 단독, 또는 더 가벼운 WebGL 래퍼 |

**설치 전에 확인한다:** 번들 크기를 감당하는지, 빌드가 ESM을 처리하는지, SSR 환경이면 클라이언트 전용으로 격리되는지.

---

## 2. SSR·정적 생성 격리 (가장 흔한 사고)

Next·Astro·Hugo 등에서 서버 렌더 시점에는 `window`·`document`·WebGL 컨텍스트가 없다. 최상위에서 three를 임포트하면 빌드가 깨진다.

- React: WebGL 컴포넌트를 **클라이언트 전용 동적 임포트**로 감싸고 SSR을 끈다.
- 정적 사이트: 스크립트를 `defer`로 두고 DOM 준비 후 초기화한다.
- 어느 쪽이든 **캔버스가 없어도 페이지가 완성돼 보여야 한다**(§4 폴백).

---

## 3. 리소스 수명 관리 (두 번째로 흔한 사고)

three는 자동으로 정리되지 않는다. 라우트 전환이나 컴포넌트 언마운트에서 직접 해제하지 않으면 GPU 메모리가 샌다.

해제해야 하는 것: geometry, material, texture, render target, 그리고 렌더러 자체.

- 애니메이션 루프를 취소한다(`cancelAnimationFrame` 또는 R3F가 관리하는 루프에서 이탈).
- 리사이즈·포인터 이벤트 리스너를 제거한다.
- 텍스처는 재사용 가능한 것을 캐시하고, 일회성은 반드시 `dispose()`한다.
- R3F는 씬 그래프에서 제거될 때 상당 부분을 정리하지만, **직접 만든 텍스처·렌더타깃은 직접 해제**해야 한다.

증상: 페이지를 몇 번 오가면 점점 느려지고 탭이 무거워진다 → 누수다.

---

## 4. 폴백은 선택이 아니다

WebGL은 실패한다 — 구형 기기, 드라이버 이슈, GPU 블랙리스트, 저전력 모드, 컨텍스트 손실.

**3중 안전망:**

1. **지원 감지** — 컨텍스트 생성이 실패하면 정적 이미지 버전으로 간다.
2. **저감모션** — `prefers-reduced-motion`이면 캔버스를 아예 만들지 않고 최종 상태 이미지를 보여준다.
3. **컨텍스트 손실 처리** — `webglcontextlost` 이벤트에서 정적 폴백으로 전환한다. 이걸 안 잡으면 화면이 검게 남는다.

폴백 이미지는 **효과가 끝난 상태의 한 프레임**이어야 한다. 빈 배경이 아니다.

---

## 5. 성능

- **DPR을 제한한다.** 레티나에서 `devicePixelRatio`를 그대로 쓰면 픽셀이 4배가 된다. 1.5~2로 상한을 둔다.
- **화면 밖이면 멈춘다.** IntersectionObserver로 캔버스가 뷰포트를 벗어나면 렌더 루프를 정지한다. 배터리와 발열에 크게 영향한다.
- **텍스처 크기를 줄인다.** 히어로 텍스처 4K는 거의 항상 과하다. 2K 이하로.
- **드로우콜을 줄인다.** 같은 재질은 합치고, 파티클은 개별 메시가 아니라 하나의 버퍼로 다룬다.
- **셰이더에서 분기를 줄인다.** GPU는 분기에 약하다.
- 모바일에서는 파티클 수·해상도를 낮춘 별도 설정을 둔다.

---

## 6. 스크롤·커서 연동

- 스크롤 진행도와 포인터 위치를 **변수에 담아 두고**, 렌더 루프에서 한 번만 읽어 반영한다. 이벤트마다 렌더를 강제하지 않는다.
- 값에 감쇠(lerp)를 준다. 원시 포인터 값을 그대로 쓰면 딱딱하고 지터가 보인다.
- R3F에서는 프레임 루프 훅 안에서 값을 갱신한다. React 상태로 프레임을 돌리지 않는다.

---

## 7. 효과별 메모

**C1 디스플레이스먼트/리퀴드** — 평면 하나 + 히어로 텍스처 + 노이즈 텍스처. 포인터 좌표로 UV를 밀어낸다. 세기를 절제하면 에디토리얼에도 어울리고, 과하면 촌스럽다.

**C2 파티클 디졸브** — 이미지를 캔버스에 그려 픽셀을 샘플링하고, 밝기/알파로 파티클 위치를 만든다. 수만 개면 인스턴싱이나 포인트 버퍼로 다룬다. 모바일에서는 샘플 간격을 넓혀 개수를 줄인다.

**B3 3D 피사체** — 이미지 → GLB 변환은 `moai-media:media-higgsfield-assets`에 위임한다. 받은 GLB는 폴리곤 수와 텍스처 용량을 확인하고, 필요하면 목표 폴리곤 수를 낮춰 다시 뽑는다. 리깅·애니메이션이 필요 없으면 켜지 않는다(비용이 더해진다).

---

## 8. 안티패턴

- **최상위에서 three 임포트** → SSR·정적 빌드 파손.
- **정리 없이 언마운트** → GPU 메모리 누수.
- **폴백 없음** → 일부 사용자에게 검은 사각형.
- **DPR 무제한** → 레티나에서 프레임 급락.
- **화면 밖에서도 렌더** → 배터리 소모, 발열.
- **CSS로 되는 걸 WebGL로** → 번들과 위험만 늘고 결과는 같다.
- **원시 포인터 값 직결** → 지터. 감쇠를 준다.

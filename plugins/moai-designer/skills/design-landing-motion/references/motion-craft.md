# motion-craft.md — 모션 규범 (DOM·CSS)

> `design-landing-motion` | 3단계에서 읽는다. WebGL은 `threejs-patterns.md`.

**Evidence tier:** 2차 (Higgsfield 공식 스킬 `higgsfield-websites` v0.12.0, MIT — `design-recipe.md` §6 모션 규칙 착안) + 웹 표준 성능·접근성 통념

---

## 1. 넣기 전에 답할 질문

애니메이션을 추가하기 전에 **"이건 무엇을 전달하는가?"**에 답한다. 넷 중 하나여야 한다.

- **위계** — 무엇을 먼저 볼지 알려준다
- **서사** — 이야기를 진행시킨다
- **피드백** — 내 입력이 닿았음을 알린다
- **상태** — 무엇이 바뀌었는지 보여준다

"멋있어서"는 답이 아니다. 답이 없으면 뺀다.

---

## 2. 성능 — 핫패스에서 건드릴 것

**`transform`과 `opacity`만 애니메이션한다.** 이 둘은 합성 단계에서 처리돼 레이아웃·페인트를 다시 돌리지 않는다.

| 하지 말 것 | 대신 |
|---|---|
| `width` / `height` | `transform: scale()` |
| `top` / `left` / `margin` | `transform: translate()` |
| `box-shadow` 애니메이션 | 그림자 레이어를 겹쳐 `opacity` 전환 |
| `filter: blur()` 연속 변화 | 미리 블러된 레이어를 `opacity`로 교차 |

프레임마다 상태를 갱신하지 않는다. React라면 프레임 값은 상태가 아니라 모션 값으로 다루고, 바닐라라면 스크롤/포인터 값을 변수에 담아 `requestAnimationFrame`에서 한 번만 반영한다.

`will-change`는 실제로 움직이는 요소에만, 움직임이 끝나면 해제한다. 남발하면 메모리를 먹고 오히려 느려진다.

---

## 3. 이징 — 스프링을 기본으로

선형·`ease-in-out`보다 스프링 물리가 자연스럽다. 감쇠가 있어야 도착할 때 딱 멈추지 않고 안착한다.

- React: Framer Motion의 스프링(`stiffness` 100 안팎, `damping` 20 안팎)을 기본으로.
- 바닐라: GSAP의 `power2.out` 계열, 또는 직접 스프링 보간.
- 커서 추종은 반드시 감쇠를 준다. 커서에 1:1로 붙으면 싸구려로 보인다.

스크롤 스크럽은 진행도에 **약간의 지연**을 준다(scrub 0.5~1 상당). 0이면 딱딱하고, 너무 크면 늘어진다.

## 4. 접근성 — 저감모션은 선택이 아니다

**모든 애니메이션 요소에 `prefers-reduced-motion` 대체를 둔다.**

```css
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```

이 전역 차단은 **최소선**이다. 그것만으로는 스크롤 핀·캔버스 루프가 안 멈춘다. 자바스크립트에서도 확인해 **핀과 스크럽 자체를 걸지 않는다**.

```js
const reduced = window.matchMedia('(prefers-reduced-motion: reduce)').matches;
if (!reduced) {
  // 핀·스크럽·파티클 초기화
}
```

저감모션에서 사용자가 보는 것은 **완성된 최종 상태**다. 빈 화면이나 첫 프레임이 아니다.

접근성은 저감모션만이 아니다:
- 키보드 포커스가 핀된 구간에 갇히지 않는지 확인한다.
- 모션이 텍스트 대비를 떨어뜨리지 않는지 본다(움직이는 배경 위 글자).
- 스크린리더 흐름은 시각 순서와 어긋나면 안 된다. 시각적으로만 재배치하고 DOM 순서를 그대로 두면 읽는 순서가 깨진다.

---

## 5. 스크롤 연동

- 스크롤 위치를 직접 읽어 매 이벤트마다 DOM을 만지지 않는다. 관측자(IntersectionObserver)나 스크롤 라이브러리의 진행도 값을 쓴다.
- **핀 구간의 높이를 명시**한다. 높이가 콘텐츠에 따라 흔들리면 스크럽 진행도가 튄다.
- 한 페이지에 핀 구간을 여러 개 두면 스크롤 감각이 무너진다. 시그니처 하나 원칙이 여기서도 적용된다.
- 스크롤 재킹(사용자 스크롤을 가로채 강제로 다음 섹션으로 보내는 것)은 하지 않는다. 스크롤은 사용자 것이다.

---

## 6. 상태와 폼 — 행복 경로만 만들지 않는다

- 로딩은 일반 스피너 대신 **최종 레이아웃 모양의 스켈레톤**으로.
- 빈 상태·오류 상태를 구성해 둔다.
- 누름 피드백: `translateY(-1px)`나 `scale(0.98)` 정도의 촉감.
- 폼: 라벨은 입력 **위**, 오류는 **아래**. 플레이스홀더를 라벨 대용으로 쓰지 않는다.
- 버튼 라벨은 자기 배경 대비 WCAG AA를 넘겨야 한다. 사진 위 고스트 버튼은 스크림이나 테두리가 필요하다.

## 7. 카피 안티슬롭 (모션과 함께 자주 무너지는 곳)

- 헤드라인 8단어 이하, 부연 25단어 이하. 섹션마다 비주얼 하나 **또는** CTA 하나.
- **같은 의도의 CTA는 페이지 전체에서 한 표현으로 통일**한다. "문의하기"와 "상담 신청"과 "연락주세요"가 한 페이지에 있으면 실패.
- 채움 동사(혁신적인·차세대·완벽한·seamless·unleash)를 쓰지 않는다.
- **지어낸 성과 수치를 쓰지 않는다**(`92% 향상`, `4.1배 ROI`, `10,000+ 팀`). 목업이라고 명시하지 않는 한 금지. 다만 가상 브랜드의 **제품 사실**(가격·용량·치수)은 필요한 콘텐츠이니 그럴듯하고 일관되게 채운다 — 금지 대상은 성과·사회적증거 주장이다.
- 가짜 후기 이름("홍길동 · 마케터")과 워터마크 stock 얼굴을 쓰지 않는다.
- "스크롤해서 더 보기" 같은 스크롤 안내 문구를 넣지 않는다.
- 인용은 3줄 이하, 출처는 이름 + 역할.
- **내보내기 전에 화면의 모든 문자열을 다시 읽는다.** 어색하거나 지시대상이 모호하면 고친다. 평범하고 기능적인 카피가 멋 부린 카피보다 낫다.

---

## 8. 안티패턴

- **모션부터 짜기** — 정적 레이아웃을 먼저 완성하고 그 위에 얹는다. 순서를 바꾸면 초기 렌더가 빈 페이지가 된다.
- **레이아웃 속성 애니메이션** — 프레임이 떨어진다.
- **저감모션 대체 누락** — 접근성 실패이자 게이트 실패.
- **커서 효과에만 의존** — 모바일에 커서가 없다. 스크롤 대응을 함께 만든다.
- **반쯤 붙은 스크롤 트리거** — 제대로 못 끝낼 것 같으면 정적으로 낸다.
- **무한 루프를 정보 섹션에 배치** — 읽기를 방해한다.

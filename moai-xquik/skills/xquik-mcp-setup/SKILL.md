# Xquik MCP 셋업

## 사용 시점

다음 요청에는 이 스킬을 우선 사용합니다.

- "Xquik MCP 연결해줘"
- "X 데이터 검색 MCP 설정"
- "트윗 검색이나 프로필 조회를 Cowork에서 쓰고 싶어"
- "X 모니터링과 웹훅 워크플로우를 MCP로 연결"
- "Xquik API 키 인증 오류 확인"

## 준비물

| 항목 | 값 |
|---|---|
| 원격 MCP URL | `https://xquik.com/mcp` |
| 문서 | `https://docs.xquik.com/mcp/overview` |
| API 키 환경변수 | `XQUIK_API_KEY` |
| 인증 헤더 | `Authorization: Bearer ${XQUIK_API_KEY}` |

API 키 원문은 사용자에게 요청하지 않습니다. 사용자가 직접 Cowork, MCP 클라이언트, 환경변수, 비밀값 저장소 중 하나에 저장하도록 안내합니다.

## 워크플로우

1. 요구사항을 확인합니다.
   - 필요한 작업: 검색, 프로필 조회, 추출, 모니터링, 웹훅, 게시 중 무엇인지 확인합니다.
   - 연결 위치: Cowork 프로젝트, 로컬 MCP 설정, 팀 공유 설정 중 어디인지 확인합니다.

2. 연결값을 설정합니다.
   - MCP URL은 `https://xquik.com/mcp`를 사용합니다.
   - 인증은 `Authorization: Bearer ${XQUIK_API_KEY}` 형식으로 설정합니다.
   - `XQUIK_API_KEY`는 클라이언트 비밀값 저장소나 환경변수에만 저장합니다.

3. 1회 검증을 실행합니다.
   - 토큰 없이 호출하면 401 응답이 나오는 것이 정상입니다.
   - 토큰 설정 후 MCP 도구 목록 조회 또는 간단한 읽기 작업으로 연결을 확인합니다.
   - 검증 결과를 "성공", "인증 오류", "네트워크 오류", "권한 범위 오류" 중 하나로 정리합니다.

4. 사용자에게 다음 작업 경로를 제안합니다.
   - 데이터 검색: 키워드, 계정, 기간 조건을 먼저 확정합니다.
   - 모니터링: 알림 대상, 주기, 웹훅 수신 URL을 먼저 확정합니다.
   - 게시: 승인 절차와 계정 권한을 먼저 확인합니다.

## 오류 처리

| 증상 | 확인할 것 | 조치 |
|---|---|---|
| 401 Unauthorized | API 키 누락 또는 잘못된 Bearer 형식 | `XQUIK_API_KEY` 저장 위치와 인증 헤더 형식을 확인합니다. |
| 403 Forbidden | 권한 범위 또는 계정 상태 문제 | 필요한 작업 권한이 있는 키인지 확인합니다. |
| 네트워크 오류 | 클라이언트의 원격 MCP 접근 가능 여부 | 방화벽, 프록시, DNS, TLS 설정을 확인합니다. |
| 도구가 보이지 않음 | MCP 클라이언트 캐시 또는 세션 상태 | MCP 연결을 재시작하고 도구 목록을 다시 조회합니다. |

## 공개 커뮤니케이션 가드

- 내부 라우팅, 비용 구조, 비공개 구현 세부사항을 공개 문서에 적지 않습니다.
- API 키, 세션, 토큰 원문을 요청하거나 출력하지 않습니다.
- 공개 설명은 기능 범위와 설정 절차만 다룹니다.
